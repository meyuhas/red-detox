## התאריכים - איפה משנים

**מקור אמת אחד:** בלוק `CYCLE` בראש `index.html`. שלושה תאריכים, וזהו.

```js
const CYCLE = {
  WEBINAR:          { date: '2026-10-04', time: '20:00', minutes: 60 },
  COURSE_START:     '2026-10-11',   // מפגש פתיחה
  LATE_JOIN_UNTIL:  '2026-10-18',   // המפגש השני - החלון האחרון למאחרים
  TIME:             '20:00',
  NEXT_CYCLE_TEXT:  'בקרוב מועד נוסף',
  TZ:               'Asia/Jerusalem'
};
```

כותבים תאריך ושעה בשעון ישראל. ההמרה ומעבר שעון קיץ/חורף מחושבים בזמן ריצה, ולכן אין מה לחשב ידנית גם כשמחזור חוצה את סוף אוקטובר.

### ארבעת המצבים

הדף עובר ביניהם לבד, לפי השעון. אין מה לתחזק.

| מצב | מתי | מה רואים |
|-----|------|----------|
| `webinar` | עד תום וובינר ההיכרות | באנר ספירה לאחור + שורת הוובינר בלוח |
| `pre` | הוובינר חלף, הסדנה טרם נפתחה | שורת הוובינר נעלמת, הספירה עוברת לפתיחת הסדנה |
| `late` | מהפתיחה ועד תום המפגש השני | "הסדנה נפתחה - עוד אפשר להצטרף" |
| `closed` | אחרי חלון המאחרים | כל התאריכים הופכים ל"בקרוב מועד נוסף" |

המצב הנוכחי נחשף כ-`data-cycle-state` על ה-`<body>`, נוח לבדיקה בדפדפן.

**לפתיחת מחזור חדש:** לעדכן את שלושת התאריכים ב-`CYCLE`, ואת ששת מועדי המפגשים במרקאפ.

### ששת מועדי המפגשים הם טקסט סטטי

הם יושבים בסקשן `לוח המפגשים` (`.sched-row`), וגם ב-`.dates-highlight-bar`, ב-`.dates-strip` שב-`final-cta` וב-`pricing-footer`. המנוע לא נוגע בהם - הם מידע להצגה בלבד. טקסט שמופיע ביותר ממקום אחד צריך עדכון בכל המקומות.

מחזור נוכחי: 11.10 · 18.10 · 25.10 · 1.11 · 8.11 · 15.11 - כולם ימי ראשון, 20:00-21:00 בזום.

אם אי פעם נוסיף כפתור "הוספה ליומן" לכל מפגש, אז ורק אז יהיה טעם להעביר גם אותם ל-`CYCLE`.

## הרשמה לוובינר ומייל התודה

הטופס יושב בסקשן `#webinar-signup`. הזרימה:

1. **Netlify Forms** קולטת את ההרשמה (טופס בשם `webinar`). נטליפיי מזהה טפסים **בזמן הבנייה** מסריקת ה-HTML - טופס חדש לא יופיע עד שתרוץ בנייה.
2. **EmailJS** שולח את מייל התודה לנרשמת, עם קישור הזום.
3. הדפדפן עובר ל-`thanks-webinar.html`, שמציג את התאריך מ-`cycle.js` וכפתורי הוספה ליומן.

**אין נפילת mailto.** הגרסה הישנה פתחה תוכנת מייל כשהשליחה נכשלה. כאן מוצגת הודעת שגיאה והמשתמשת נשארת בדף.

### התלות בתבנית של EmailJS

חשבון `oren` ב-EmailJS · שירות `service_7ge3b4c` · תבנית `template_88c6ks8`.

שני דברים בתבנית **אינם בקוד** ולכן קל לשבור אותם:

- **שם המשתנה הוא `date`**, לא `webinar_date`. הקוד שולח `Cycle.short(webinarStart)`, כלומר `4.10` בלבד.
- **המילים "יום ראשון" כתובות קשיח בתבנית**, לפני `{{date}}`. כל עוד הוובינר ביום ראשון זה תקין. אם ייקבע ביום אחר - צריך לתקן את התבנית, לא את הקוד.
- **קישור הזום מגיע מ-`cycle.js`** דרך המשתנה `{{zoom}}`. כשהילה יוצרת את הפגישה - מדביקים את הקישור ב-`ZOOM_LINK` ודוחפים. אם הוא ריק, המייל יכתוב שהקישור יישלח לפני המפגש במקום להציג קישור מת.

מכסת EmailJS בתוכנית החינמית: 200 מיילים לחודש, מתאפסת ב-22 לחודש.

## מלכודות

- **הווידאו דחוס במכוון.** המקור היה 131MB ב-20Mbps, מעל המגבלה של גיטהאב (100MB לקובץ) ואיטי בטירוף לדף נחיתה. הגרסה כאן 17MB. המקור נשמר ב-`~/GitHub/red-detox/untitled folder/video.mp4` ואינו במעקב.
- **ה-PNG כבדים** - כ-8MB בסך הכל, `hero.png` לבדו 2.1MB. עובד, אבל שווה המרה ל-WebP.
- **`FORMSPREE_ID` הוא עדיין `YOUR_FORM_ID`** - טופס לא מחובר. ההרשמה עוברת דרך קישורי iCount.
- **`ZOOM_LINK` ריק.** ממתין לקישור.
